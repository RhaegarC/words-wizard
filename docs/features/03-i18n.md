# Feature 03 — Bilingual UI (i18n)

> Priority: Must · Mission 1 · **Status: In review**
> Depends on: 01, 02

## Summary

The product is bilingual, not English-with-a-translation-screen. Every fixed string — navigation,
buttons, hints, feedback, empty states, errors, accessibility labels — lives in `locales/en.json`
and `locales/zh.json`, and the active locale comes from the profile. Chinese is the default on
`zh-*` devices. Word content is selected by the same locale (feature 04 supplies the fields).

## User story

As a **Chinese-speaking child**, the app speaks my language by default, and I can switch to
English in Settings when I want to. As a **developer**, I cannot ship a key that exists in one
language and not the other.

## Acceptance criteria

- [x] `src/public/locales/en.json` and `src/public/locales/zh.json` exist, with flat dotted keys
      grouped by namespace: `common.*`, `boot.*`, `create.*`, `install.*`, `topics.*`, `home.*`, `session.*`,
      `feedback.*`, `modes.*`, `words.*`, `review.*`, `character.*`, `settings.*`, `errors.*`.
- [x] `t(key, params?)` interpolates `{name}` placeholders and falls back to the English string,
      then to the key itself; a missing key logs a dev-only warning.
- [x] Plural-sensitive copy uses a `_one` / `_other` suffix pair resolved with `Intl.PluralRules`
      for the active locale; Chinese resolves to `_other`.
- [x] Default locale: `navigator.language` starting with `zh` → `zh`; otherwise `en`.
- [x] The active locale is `Profile.locale`, persisted by feature 05; `setLocale()` updates the
      profile and re-renders without a reload.
      *Until 05 lands, `LocaleProvider` persists the choice under `words-wizard.locale` in
      `localStorage` so the manual check survives a reload.*
- [x] `<html lang>` is `zh-Hans` or `en` and updates with the locale.
- [x] Every fixed string in the MVP screens is a key; no user-visible English literal remains in
      JSX except the target word, IPA, and word content.
      *The dev-only route table keeps English tooling copy; it is stripped from the production
      bundle.*
- [x] Word-content helpers select by locale: `wordMeaning(word, locale)` returns `meaningZh` or
      `meaningEn`; `wordDefinition` and `wordExample` do the same.
- [x] Speech language comes from i18n: English words use an `en-*` voice; UI read-aloud uses a
      `zh-*` voice when the locale is Chinese.
- [x] The CJK font stack is a system stack (`-apple-system`, `"PingFang SC"`, `"Microsoft YaHei"`,
      `"Noto Sans SC"`, sans-serif); no webfont is bundled.
- [x] The key-parity test fails in **both** directions: a key only in `en` and a key only in `zh`.

## Tasks (ordered)

1. Create `src/public/locales/en.json` with the full MVP copy inventory (start from the prototype's
   strings and PRD Appendix A.3 empty states).
2. Create `src/public/locales/zh.json` with the same key set; have a Chinese speaker review tone,
   not just literal accuracy (child-facing, encouraging, no punitive words).
3. Implement `src/i18n/t.ts`: key typing from `en.json`, interpolation, plural resolution,
   English fallback, dev warning.
4. Implement `src/i18n/LocaleProvider.tsx` and `useLocale()`; read `Profile.locale` when a profile
   exists, otherwise the device default.
5. Implement `setLocale(locale)` against the persistence layer (a stub until feature 05).
6. Add `wordMeaning`, `wordDefinition`, `wordExample` selectors in `src/i18n/content.ts`.
7. Add `speechLangFor(locale)` in the speech helper's vocabulary (`en-US` / `zh-CN`).
8. Replace hardcoded strings in the promoted prototype screens with `t()` calls.
9. Set `<html lang>` and mount the CJK font stack in `src/index.css`.
10. Add the key-parity and interpolation tests.
11. Manual pass: every screen in both locales, no overflow from longer Chinese or English copy.

## Implementation notes

- `src/i18n/messages.ts` — `interpolate`, `createTranslator`, and the `MessageKey` type. The type
  is derived from `en.json`; plural families are callable by their base key (`home.streakDays`).
- `src/i18n/catalog.ts` — imports both JSON files statically, so `t()` is synchronous and the copy
  ships in the offline bundle. The same files are still copied to `dist/locales/` from `public/`.
- `src/i18n/locale.ts` — `defaultLocale`, `htmlLang`, `ENGLISH_SPEECH_LANG`, `speechLangFor`.
- `src/i18n/content.ts` — `wordMeaning`, `wordDefinition`, `wordExample`.
- `src/i18n/LocaleProvider.tsx` — `LocaleProvider` and `useLocale()`; sets `<html lang>` and
  re-renders translators on switch.
- `src/router/routes.ts` — `titleFor` became `titleKeyFor`, returning a `MessageKey` so the shell
  translates titles instead of receiving English.
- `src/dev/RouteTable.tsx` — gained a locale toggle for the manual pass.

## Tests

**Unit (Vitest):** 49 tests pass across 9 files.

- `keys.test.ts` — the two locale files have identical key sets in both directions; every value is
  non-empty; every `{placeholder}` in `en` also appears in `zh` for the same key; all 14
  namespaces are present; every `_one` key has an `_other` partner.
- `messages.test.ts` — interpolation, untouched placeholders, plain keys with a `count`, plural
  `_one`/`_other`, Chinese `_other`, English fallback, missing-key warning, key typing.
- `locale.test.ts` — `zh`, `zh-CN`, and `zh-Hans` → `zh`; `en-GB`, `fr-FR`, `undefined`, and `""`
  → `en`; `htmlLang`; `speechLangFor`.
- `content.test.ts` — word selectors return the right language field for each locale; an
  out-of-range example index returns `""`.

**Verification (manual):**

- `pnpm typecheck`, `pnpm test`, and `pnpm build` pass; the production preview serves
  `/locales/en.json` and `/locales/zh.json` with 200 and the dev route table is absent from the
  bundle.
- First launch on a `zh-CN` browser shows Chinese; on `en` shows English.
- Switching locale in Settings updates the current screen without reload and persists after reload.
- No clipped buttons or wrapped labels at 1024×768 (iPad landscape) in either locale.

## Non-goals

- No third language, no RTL, no locale-specific imagery.
- No translation-management service; the JSON files are the source.
- No bundling of a CJK font.
